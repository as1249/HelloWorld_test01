实验二的第二周：用例模型与用例规约
一、 核心参与者与用例识别
执行者（Actors）：
1. 系统管理员：负责系统的基础配置与节点接入。
2. 安全审计员：负责日常监控查看和日志安全审计。
核心用例（Use Cases）：
系统管理员：登录系统、添加监控节点、设置告警阈值、管理用户权限。
安全审计员：登录系统、查看实时监控大盘、查看篡改告警、导出审计报表。
二、 用例规约文档（依据规范书写）
用例编号：UC01
用例名称：添加监控节点
执行者：系统管理员
前置条件：管理员已成功登录系统，并获取了目标 Linux 服务器的 IP 和 SSH 凭证。
后置条件：系统成功与被监控节点建立连接，并在界面上显示该节点状态为“在线”。
涉众利益：管理员希望能快速接入新服务器；系统需要保证连接过程的安全。
基本路径：
1. 管理员发起“添加节点”操作。
2. 管理员输入节点名称、IP 地址、SSH 端口和认证密码。
3. 系统验证输入信息的格式是否正确。
4. 系统通过 SSH 协议尝试连接该服务器。
5. 系统提示“连接成功”，并在节点列表中展示该服务器。
扩展路径：
3a. 输入信息格式错误（如 IP 不合法），系统提示“请输入正确的 IP 地址”，返回基本路径第 2 步。
4a. 系统 SSH 连接超时或密码错误，系统提示“连接失败，请检查网络或凭证”，用例结束。
用例编号：UC02
用例名称：查看日志篡改告警
执行者：安全审计员
前置条件：审计员已登录系统，且系统底层监控 Agent 正常运行。
后置条件：审计员掌握被篡改日志的详情（时间、路径、修改前后的哈希值）。
涉众利益：安全审计员需要尽快定位攻击行为，追溯攻击源头。
基本路径：
1. 审计员进入“告警中心”。
2. 系统展示所有未处理的告警列表。
3. 审计员选择一条类型为“日志文件篡改”的告警。
4. 系统展示该告警的详细信息，包括被修改文件的绝对路径、发生时间。
5. 系统向审计员展示原始日志的哈希指纹与当前日志的哈希指纹对比。
扩展路径：
2a. 如果当前没有未处理的告警，系统提示“暂无未处理告警”，用例结束。
